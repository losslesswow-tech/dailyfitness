# 参考调研与界面方案

调研日期：2026-11-03。范围为官方帮助、开源仓库 README 与官方界面截图。未安装这些软件进行真机体验，未逐行审查其实现；本轮结论属于产品流程与界面规划。

后续状态：用户已要求实现初版 Demo，且确认哑铃默认总重。Demo 0.1 的已实现功能、安装方式和剩余边界见根目录 README.md；本文件继续保留实现前的参考依据。

## 1. 用户已经确定的原则

- 日历为首页，选日期后在下方看到运动、饮食和睡眠报告。
- 三分化是三个训练日，每日一个部位；四、五、六分化同理。
- 从六个部位选择训练日的部位，同一个部位可包含多个动作。
- 只自动继承上次重量，次数由用户录入。
- 优先简单易用，多参照成熟软件和开源项目。
- 本轮先修订规划，尚未进入正式应用开发。

## 2. 参考对象与采用方式

以下“采用方式”是本项目的设计判断，不能视为来源软件为本项目提供的建议。

| 对象 | 官方资料确认的做法 | 本项目采用方式 |
| --- | --- | --- |
| Hevy，现有产品 | 从空白训练、已有模板、复制历史三条入口开始；逐组记录，最后结束训练 | 提供快速记录与计划训练两条主入口；按行记录组，展示上次结果；复制训练只生成待完成结构 |
| Strong，现有产品 | 完成一组后启动休息计时，可更改时长、跳过，并按动作设置 | 计时放在训练页内，可选启用，不强迫用户跳到独立页面 |
| FitNotes，Android 产品 | 月历日期标记、日期下方训练面板；动作按肌群查找，支持历史、单组修改和备注 | 首页采用上方日历、下方当日报告；部位和器械筛选动作；记录后仍可修正单组 |
| LiftLog，开源 | 本地记录、无需注册、离线训练；训练模板、休息计时、进度图表 | 本地数据库和恢复草稿优先；训练页只显示当前任务需要的信息 |
| wger，开源 | 分别管理训练计划、身体测量、饮食与动作数据 | 数据结构区分模板、训练日、真实场次、组记录；作为业务模型参考，不直接接入其服务器 |
| Waistline，开源 | 以日期和用餐时间组织饮食日记，提供导入导出 | 饮食按餐次和时间排列，顶端展示当天汇总；备份恢复是第一版能力 |

## 3. 实际查看的官方界面

### FitNotes 日历

[官方截图](https://www.fitnotesapp.com/images/Calendar_Month_View_Workout_Panel.png)显示上半屏月历、日期下方的小圆点，以及下半屏所选日动作与逐组重量次数。

采用其信息结构。日历下方扩展为运动、饮食和睡眠三个分区，中文标签明确区分。截图为较早风格，不沿用其旧式顶栏、细小文字或紧密触控区域。

### Hevy 训练记录

[官方教程截图](https://help.hevyapp.com/hc/article_attachments/35388406647703)显示快捷开始、训练模板、动作标题、休息时间，以及“组 / 上次 / 重量 / 次数 / 完成”的逐行布局。

采用表格列关系和主动作位置。S24 窄屏仅保留必要列，“上次”在空间不足时放到本组下方；RPE 不作为第一版必填字段。教程图片为 iPhone 外观，实际应用使用 Android 原生导航、键盘与返回规则。

### LiftLog 训练记录

[官方截图](https://liftlog.online/assets/img/workoutpage.png)以动作分区和大块组卡片呈现记录，界面留白较多，并显示历史结果与休息倒计时。

借鉴清晰的动作分区和足够大的操作目标。对于本项目经常更换重量、逐组手输次数的场景，优先采用竖向组列表，避免横向组卡片增加滚动；浮动计时器不得遮挡当前输入与保存按钮。

这些截图仅用于规划核对，不作为本应用的图片或品牌资产。

## 4. 第一版功能取舍

### 必须完成：用户原始需求

日历与每日报告；所有指定有氧项目及字段；分化计划与三大项；部位图和自定义动作；逐组记录与重量继承；饮食餐次和营养素换算；跨夜睡眠；身体测量历史；身体、运动、饮食曲线；修改删除；离线保存；可安装 APK。

### 随核心流程加入：让记录实际可用

- 动作搜索、按部位与器械筛选、最近使用。
- 训练计划与训练日模板，可复制、排序和修改动作；无需每次重新建计划。
- 上次记录就近展示；本次次数仍手动输入，不能默认标为完成。
- 热身组与正式组标记，组间休息计时可开关。
- 动作备注与历史查询。
- 自动保存，训练中断或离开后可恢复。
- 单组修改删除、删除训练前确认。
- 完成训练后的简洁汇总，以及备份恢复。

### 后续增强

RPE / RIR、超级组、递减组、1RM 估算、个人纪录提示、配片计算器、训练提醒、食物库、健康数据同步。第一版不因这些扩展推迟原始需求。

不自动建议加重量，不根据完成一次训练擅自调整用户目标；本应用首先是记录工具。

## 5. 四个入口的布局

### A. 日历：默认首页

从上到下：

1. 当前年月、切换月份、回到今天。
2. 月历网格。选中日期明显；有氧 / 力量、饮食、睡眠用可识别标记并配图例。
3. 所选日期标题。历史日期录入时显式显示日期，避免误记到今天。
4. 三个快捷动作：添加运动、添加饮食、添加睡眠。
5. 运动报告：有氧时长；力量动作与分组摘要；有进行中训练则显示继续入口。
6. 饮食报告：摄入 kcal、三大营养素、基础代谢估算参照，展开查看各餐。
7. 睡眠报告：跨夜起止时间、时段长度、是否起夜。
8. 底部导航：日历 / 训练 / 趋势 / 我的。

顶部日历与底部报告处于同一滚动页面，报告较多时允许折叠月历；避免日历长期占满空间。无记录时直接提供添加入口。

计划日期与已有记录使用不同标记和文字说明。未开始或未完成的计划不进入实际运动量统计。

### B. 训练：计划与动作

从上到下：

1. 进行中训练入口（若存在）。
2. 快速开始：有氧 / 三大项 / 自由记录。
3. 我的计划卡片，例如“三分化：胸 → 背 → 腿”，同时显示当前训练日。
4. 展开计划后显示训练日列表，每日一个部位，可查看或调整动作顺序。
5. 点击“开始第 N 训练日”进入实际训练；新增计划和动作库作为次要入口。

分化计划不默认等于每周训练 N 天，不要求连续自然日执行。每个训练日选一个部位，可插入休息日；完成本场训练后才建议下一个训练日，用户可手动选择。

### C. 正在训练：独立专注页面

从上到下：

1. 场次标题、日期、持续时间与结束本次训练入口。
2. 当前训练部位与动作顺序。
3. 当前动作名、器械、上次训练日期与历史入口。
4. 已记录组列表：组号、上次参考、重量、次数、完成状态。
5. 当前组输入：重量和次数，重量单位及单只 / 合计口径保持可见。
6. 主按钮“记录一组”。只有成功保存才更新完成状态。
7. 可折叠的休息计时、备注和“完成动作 / 下一动作”。

“完成动作”与“结束本次训练”使用不同文案和位置。完成某个动作后仍可回看和修正，结束整场训练时展示动作数、组数和训练容量。

首次进入新动作自动继承最近一次相同动作与器械的重量，显示来源日期；次数保持待填写。模板的目标次数仅为参照。进入历史补录时继承所选日期之前最近的记录，避免从未来训练取值。

第一版同一时间最多保留一场进行中训练；新开训练前提供继续或明确放弃旧草稿的选择，不能静默覆盖。

### D. 趋势

顶部日期范围，下面为身体 / 运动 / 饮食 / 睡眠切换。每次仅展示一个主要指标及单位；折线图下显示本期汇总和可读数据表。

体重、围度和体脂按实际测量点绘制。有氧可按类型筛选；力量可切换动作、组数与容量；饮食显示每日 kcal 和营养素。没有记录与真实数值为零分开处理。

### E. 我的

当前资料 → 新增身体测量 → 历史测量 → 自定义项目 → 器械与单位设置 → 备份与恢复 → 计算来源与版本。

## 6. 三分化的具体数据示例

示例计划“我的三分化”，供说明结构，不自动代替用户建计划：

| 训练日 | 唯一部位 | 可编排多个动作 |
| --- | --- | --- |
| 第 1 训练日 | 胸 | 杠铃卧推、哑铃卧推、俯卧撑 |
| 第 2 训练日 | 背 | 坐姿划船、哑铃划船 |
| 第 3 训练日 | 腿 | 深蹲、弓步蹲 |

计划训练日只有一个部位。当天动作从该部位的动作库筛选；三大项保留独立快速入口。模板可设目标组数，只有实际点击记录的组计入训练报告。

实体分层：计划 → 计划训练日 → 模板动作；真实训练场次 → 场次动作 → 实际组。场次保存计划和器械口径快照，后续修改模板、动作名或杆重不改变过去报告。

## 7. 界面与操作约束

- 原生 Android 风格，中文优先，浅色为首个设计目标；提供适应系统主题的扩展空间。
- 色彩辅助区分模块和状态，名称、选中态和完成状态仍有文字或图形依据。
- 使用系统字体，数字和单位紧邻，触控区域足够大，支持系统字号放大。
- 日历每格和表单控件使用明确的可访问名称；人体图有胸肩背腿臂腹文字入口。
- 软键盘出现后，当前字段、错误提示与保存按钮仍可到达。
- 操作按钮使用“记录一组”“完成动作”“结束本次训练”等具体名称。
- 持久化成功才提示已保存；失败保留输入，避免产生假的完成状态。
- 只保存用户真实记录，示例数据与原型演示数据不能进入正式数据库。

## 8. 参考与复用策略

第一版按以上产品流程独立实现 Android 原生界面。LiftLog 当前采用 React Native / Expo，wger 为服务端体系，Waistline 采用 Cordova；它们可作为流程和模型参考，不能直接当成本项目 Kotlin 原生代码。

如后续直接使用第三方源码、动作数据库或图片，先核对具体文件和数据的许可及署名要求，再决定依赖方式。本轮未引入第三方源码、动作图片或品牌标识，官方截图仅放在本地忽略目录供调研。

可供核查的仓库许可说明：[LiftLog](https://github.com/LiamMorrow/LiftLog)、[wger](https://github.com/wger-project/wger)、[Waistline](https://github.com/davidhealey/waistline)。具体复用以选定版本的许可文件为准。
