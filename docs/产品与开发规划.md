# daily fitness：产品与开发规划

状态：2026-11-03 已进入 Demo 0.3 开发与验证，新增清空数据、运动消耗估算和官方中文食品库，并保留食物估算、运动互算和泳池计趟。本文为完整产品目标；当前可试用范围与限制见根目录 README.md。已确认“分化按训练日划分，每日一个部位”及“哑铃默认总重”。

目标：制作可安装在三星 Galaxy S24 上的中文安卓应用，以日历为首页，记录运动、饮食、睡眠及身体变化。

## 1. 产品边界

- 第一版以离线、个人使用为主，不强制登录，不依赖服务器。
- 用户真实数据初始为空；首次进入引导填写身体资料。
- 提供本地备份导出和恢复，避免更换手机或卸载时丢失记录。
- Demo 0.2 应用户要求加入可信来源食物库搜索和按重量估算；不加入图片食物识别、社交、穿戴设备同步、云账户或自动训练建议。
- Demo 0.1 先交付可安装的离线试用包；完整产品按本文继续迭代。

## 2. 页面结构

底部导航调整为四项：日历、训练、趋势、我的。日历仍为默认首页；训练页集中放计划和动作，减少首页层级。参考依据和详细页面布局见 [参考调研与界面方案](参考调研与界面方案.md)。

### 首次使用

欢迎页 → 身高 / 体重 / 性别 / 年龄 → 可选腰围 / 臂围 / 预估体脂 → 开始记录。

资料字段附单位，数值校验在本地完成。未成年人可以保留记录功能，第一版不展示只适用于成年人的代谢估算。

### 日历页（默认首页）

1. 顶部显示年月、上月 / 下月、回到今天。
2. 月历默认选中今天；日期以运动、饮食、睡眠标记提示当天已有记录，不只用颜色区分。
3. 选择日期后，下方切换到该日的报告，提供添加运动、饮食、睡眠三个快捷入口。
4. 有氧报告显示类型和时长，展开看专项数据。
5. 力量报告显示动作、重量、次数与组数；不同重量或次数分别分组显示。
6. 饮食报告显示全天摄入 kcal、三大营养素和代谢估算范围；展开查看各餐。
7. 睡眠报告显示入睡时间、起床时间、时段长度和是否起夜。
8. 已保存记录可查看、修改和删除；删除给出明确确认。
9. 今日有计划时显示“今日训练 / 下一训练日”入口；计划以轮廓或文字标记，已完成记录以实心标记，两者不能混淆。

### 训练页

- 我的计划：三 / 四 / 五 / 六分化；每个计划包含对应数量的训练日，每日一个部位。
- 每个训练日可编排同一部位的多个动作、动作顺序、计划组数、可选目标次数和组间休息时间。
- 快速开始：有氧、三大项、自由记录，不要求先创建计划。
- 动作库：按部位与器械筛选，支持搜索、自定义动作和最近使用。
- 进行中训练：离开记录页后保留“继续训练”入口。
- 复制历史训练时只复制结构和参考数据，历史已完成组不能自动变成本次已完成组。

### 趋势页

- 时间范围：近 7 天、近 30 天、近 90 天及自定义日期。
- 身体：体重、腰围、臂围、预估体脂分别切换，保留各自单位。
- 有氧：每日时长，以及支持距离的运动的距离；支持运动类型筛选。
- 力量：每日组数、次数、训练容量，并可查看具体动作的重量变化。
- 饮食：每日摄入 kcal，三大营养素可分别查看。
- 睡眠：每日记录的睡眠时段长度。
- 缺失数据不当成零，身体测量点保留实际记录日期；图表提供可读数值与空状态。

### 我的页

- 当前身体资料、添加测量、测量历史。
- 自定义有氧项目和力量动作管理。
- 杠铃默认杆重设置（初始 20 kg）。
- 导出备份、恢复备份。
- 计算规则、数据来源与版本信息。

## 3. 运动模块

### 有氧项目与字段

所有项目都填写运动时长（分钟）；距离统一以 km 存储，游泳界面可输入 m 并换算。

| 项目 | 额外字段 |
| --- | --- |
| 跑步、骑行、散步 | 距离、速度任选一项，按总时间补算另一项 |
| 游泳 | 泳姿，25/50/75/100 m 泳池，单程趟数、总时间，自动计算距离和速度；兼容手动距离记录 |
| 爬坡 | 距离、速度、坡度（%） |
| 登山 | 高度（m，建议命名为累计爬升） |
| 爬楼 | 层数、每层台阶数；自动显示总台阶数 |
| 跳绳 | 个数 |
| 健身操、球类运动 | 第一版仅时长 |
| 划船 | 建议支持时长与距离，速度自动换算 |
| 自定义项目 | 用户命名，第一版默认只需时长；可选启用距离字段 |

距离与速度统一以 km 和 km/h 保存；界面可切换 m / km，以及 km/h、分钟/公里、小时/公里。总时间必填，距离或速度有一项即可自动补算另一项，最后编辑的距离或速度作为计算依据，单位切换不改变物理量。爬坡另填坡度，坡度不参与速度 × 时间的距离换算。游泳按单程趟数计算，一个来回为两趟。

### 力量训练：分化训练

已确认定义：N 分化 = N 个训练日，每个训练日一个部位。它不是每次训练选 N 个部位，也不要求连续 N 个自然日完成。

三分化示例：第 1 训练日胸、第 2 训练日背、第 3 训练日腿。实际部位由用户从胸、肩、背、腿、臂、腹选择；示例不作为自动推荐的训练处方。四、五、六分化使用相同规则扩展训练日数量。

建计划流程：选分化 → 为每个训练日选择一个部位 → 添加该部位的动作 → 编排动作与计划组 → 保存计划。

实际训练流程：选计划中的训练日 → 开始本次训练 → 选择动作 → 逐组记录 → 完成动作 → 下一动作 → 结束本次训练并查看报告。

训练日可按顺序轮转或由用户手动选择，允许插入休息日和改期。第一版默认按顺序执行；只有用户确认结束本次训练后才推进到下一训练日，结束时有未完成内容则提示。放弃草稿不推进；历史补录和编辑不自动改变当前进度。计划进度允许手动调整。

六个部位为胸、肩、背、腿、臂、腹。用中性人体前后视图表示，背部在后视图选择，保留文字按钮作为等价入口，避免只能依赖图形点选。

器械为自重、哑铃、杠铃、杠铃片、壶铃。分化含义已确认；用户已确认哑铃默认总重，录入和统计均采用实际使用的哑铃合计重量，不再额外乘以 2。

### 力量训练：三大项

卧推、深蹲、硬拉 → 输入重量与次数 → 记录一组 → 完成动作。

三大项的快速入口仍沿用相同的逐组记录逻辑，默认杠铃器械；为每个动作分别保存重量历史。

### 进行中的动作

- 界面明确显示“运动中”、动作名称和已完成组。
- 每次点击“记录一组”，立即保存重量、次数和记录时间。
- 下一组保留重量，次数由用户重新填写，避免把默认次数误记为已完成。
- 动作与器械组合默认继承最近一次训练的重量；没有历史时允许手动录入。
- 可以同一重量连续记录，也可以变更重量继续记录。
- 点击“完成动作”才进入下一动作；未完成动作以草稿保存，重启应用可继续。
- 支持修改或删除误记的组；放弃草稿时明确提示已有组数。
- 未完成动作在日历中有“进行中”提示，不混入已完成统计。
- 动作页采用“组号 / 上次记录 / 本次重量 / 本次次数 / 完成状态”的行布局。上次次数只作参考，本次次数由用户输入。
- 增加可选的组间休息计时，记录一组后自动启动，可调整、跳过或关闭；第一版不默认申请通知权限。
- 区分热身组与正式组，统计显示各自口径。
- 支持动作备注、动作历史与一键复制训练模板；目标组不等于完成组。

### 重量口径（建议，待确认）

- 界面保存“输入重量”和“杆重”，不把两者混成一个无法追溯的字段。
- 杠铃输入为两侧杠铃片总重，不含杆；杆重默认 20 kg，可按实际器械修改。
- 示例：输入片重 40 kg，杆重 20 kg，实际总重 60 kg。
- 报告清楚展示输入口径；训练容量使用实际总重 × 次数并求和。
- 杠铃片、壶铃按实际使用总重记录；自重默认额外负重为 0，不把身体重量自动混入外部负重容量。
- 不同器械的容量建议分开查看，避免把自重、哑铃与杠铃直接比较；Demo 汇总注明为外部负重容量，不用于器械间比较。
- 哑铃默认输入总重量，显示“总重 kg”；不再自动翻倍。杠铃保存当次杆重快照，修改新动作杆重不重解释历史数据。

## 4. 饮食模块

- 餐次：早饭、中饭、下午茶、晚饭、夜宵、练后餐。
- 进入录入页时，默认填充当前本地时间，允许修改。
- 从历史日期进入时，日期沿用选中日期，不因当前时间跳回今天。
- 同日可添加多个练后餐，依次命名练后餐、练后餐二、练后餐三等；删除后不重命名已有记录。
- 输入蛋白质、碳水、脂肪的克数，允许小数和某一项为 0，至少一项大于 0。
- 实时计算 kcal，保存后按日期汇总。
- 此处输入的是营养素重量，并非食物整体重量。

计算：摄入 kcal = 蛋白质 g × 4 + 碳水 g × 4 + 脂肪 g × 9。

Demo 0.2 新增按名称选择食物、填写可食用重量的估算入口。数据来自 USDA FoodData Central 的 Foundation 2026-10-29 与 SR Legacy 2018-04 本地快照；保留原名、FDC 编号、版本与营养值快照。按食物录入采用数据库能量；手动修改营养素后改用 4/4/9 并显示提示。详细来源与转换口径见 [食物数据说明](食物数据说明.md)。

来源：USDA Food and Nutrition Information Center，https://www.nal.usda.gov/programs/fnic 。作为常用营养素能量估算，不把纤维、糖醇等特殊成分拆分计算。

### 基础消耗的显示

采用 Mifflin–St Jeor 成人静息代谢估算：10 × 体重 kg + 6.25 × 身高 cm − 5 × 年龄，男性加 5，女性减 161，单位 kcal/日。

为满足范围显示，可将公式值上下浮动 10%，在界面注明“估算展示范围”，不声称是个人实测值或统计置信区间。未提供公式所需性别时显示两个系数共同覆盖的范围，或不显示数值，具体交互在实现前确定。

此值用于参照，不是每日总消耗，也不是建议摄入目标。历史日期优先使用当时已记录的身体资料；当天没有适用资料时提示补充，不能用未来体重倒推历史。

原始公式来源：https://pubmed.ncbi.nlm.nih.gov/2305711/ 。

## 5. 睡眠模块

- 手动填写完整的入睡日期时间与起床日期时间，起夜为是 / 否。
- 记录归属于起床当天，例如 11 月 2 日 23:30 至 11 月 3 日 07:00，显示在 11 月 3 日。
- 默认入睡为所选日期前一天晚上、起床为所选日期早上，允许更改实际日期和时间。
- 检查起床晚于入睡；不能只用时钟做相减，否则会把跨夜算成负数。
- 第一版每个起床日期保留一条主要睡眠记录，再次保存视为编辑并明确提示。
- 时长为起止时间之差；只有是否起夜时，不猜测并扣除起夜时长，界面写明这是记录时段。
- 如未来需要午睡、多段睡眠，再扩展为同日多条，第一版不擅自加入。

## 6. 身体测量与数据

每次保存身体资料都形成一条带记录时间的测量，不覆盖历史。必填身高、体重、性别、年龄；可选腰围、臂围、预估体脂。修改当前资料是新增测量；修正旧记录与新增测量应是两个明确操作。

建议数据实体：

| 实体 | 关键内容 |
| --- | --- |
| 身体测量 | 身高、体重、性别、年龄、围度、体脂、测量日期、创建时间 |
| 分化计划 | 名称、分化数量、当前训练日、版本、是否启用 |
| 计划训练日 | 所属计划、顺序、唯一部位、动作编排与目标组 |
| 有氧记录 | 日期、类型、时长、距离、速度及专项字段 |
| 力量动作 | 名称、部位、器械、所属训练类型 |
| 训练场次 | 归属日期、计划与训练日快照、开始结束时间、完成状态 |
| 场次动作 | 所属场次、动作名称和器械快照、部位、杆重、重量口径、完成状态 |
| 训练组 | 所属场次动作、输入重量、次数、热身或正式、记录顺序、记录时间 |
| 饮食记录 | 日期、时间、餐次、展示名称、三大营养素 |
| 睡眠记录 | 归属日期、入睡和起床时间、是否起夜 |
| 自定义项目 | 类型、名称、启用字段、归档状态 |

通用规则：稳定 ID、本地日期用于日历归属、时间戳用于先后顺序、删除或修改不破坏其他日期。备份带版本号，导入先完整校验，再一次性替换；失败保留原数据。

计划模板与真实训练记录分开保存。修改计划、动作名称或默认杆重，不回写历史场次；模板更新由用户选择应用到未来训练。

## 7. 技术路线与交付

建议正式版采用 Android 原生 Kotlin + Jetpack Compose + Room，单机数据库负责持久化，ViewModel 管理状态，系统文件选择器处理 JSON 备份。图表与人体部位图保持本地绘制，不依赖联网图片。

Demo 0.1 为快速试用采用本地 Web 界面 + Java Android WebView 安装壳。Android 使用私有文件与 AtomicFile 保存版本化 JSON；浏览器预览使用 localStorage；两者都可导出相同格式的 JSON 备份。Demo 无网络权限。此阶段路线已向用户说明，不把 Demo 称为已完成的 Kotlin / Room 原生版。

理由：本项目只面向安卓，原生方案方便适配返回手势、软键盘、系统文件存取和后续 Android 健康数据接口。现有少量 Web 基础文件仅属于先前起步文件，不决定正式技术路线；确认规划后再确定是否保留为预览。

目标：适配三星 S24 的实际 Android 版本、中文字体与系统字号、手势导航和窄屏。Demo 已补齐项目内便携 JDK 17 和 SDK 35，最低 Android 8.0 / API 26，target SDK 35。未连接 S24 真机，仍需手机安装试用反馈。

交付内容为完整源代码、可侧载 APK、安装与备份说明。首个测试包使用本地开发签名；后续更新需保留相同签名和数据库升级逻辑。正式商店发布与商店账户不包含在第一版。

## 9. 已确认内容与尚待确定的细节

已确认：三分化指三个训练日，每日一个部位；四、五、六分化同理。哑铃默认总重。多参照开源项目与现有健身记录软件的功能和布局。先规划，再实施；用户现已要求开发可试用 Demo。
